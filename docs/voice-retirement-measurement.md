# Voice retirement and LFO phrase observation (#309)

Inactive voices with a set gate can suppress NOTE-triggered LFO reset, and that
choice can change PCM. In the focused MIDI workloads below, those gates still
belong to held keys. No orphaned gate was found in the sampled focused states.
This is evidence about phrase semantics, not evidence of a retirement bug.

**Recommendation for the owner:** retain the current behavior for this package.
Do not merge a generic retirement helper or file a speculative fix solely because
the alternative produces different PCM. If a later unification is wanted, first
decide whether a fresh phrase means no logically held notes or no sounding voices,
and how one-shot percussion differs. This report does not close #309 or record an
owner decision; it supplies the measurement needed for that decision.

## Source and host identity

- Firmware source: `1523fd0e9bb1483082ba5a71834e7255c04e7ff5`.
- Exact MIT Engines pin: `9630426f5c4a34a209ca851356fbe8ba3c4c6d19`.
- Host: macOS arm64, Apple Clang 21.0.0 (`clang-2100.3.34.2`), CPython 3.12.15.
- Standard profile, `-O2 -w -DFELUCCA_ARENA_CHECK=1`, the existing host include
  paths and `-DRV_COUNTERFACTUAL=0` or `1`. The existing harness's warning
  suppression is retained; this is not warning-free target-build evidence.
- The explicit local CC0 input directory contains eleven WAVs plus its notices.
  The normal sample generator produced five sets, eleven zones, 126,244 bytes of
  ADPCM and a 44,100-sample SLICE BREAK. The generated sample header SHA-256 is
  `d72405f100494dce4c3bff53de584423b0ab96cf9b196a85487b13206ae032bc`.

The driver exports committed source and the exact engine objects into a new
ignored directory, copies and hashes the explicit sample inputs, and generates
only host profile/DSP/FM6/sample headers. It retains all source bytes, measurement
overlays, generated headers, compiler commands, diffs, event/state JSONL and raw
stereo signed-32-bit PCM. Disposable Git indexes/HEADs inside the snapshots let the
existing profile generator verify the actual source pins. They read original
objects through alternates and do not modify the original repositories. Snapshot
build identity can be dirty because of the explicit host overlays; it is not an
installed-device identity. The manifest records those overlays separately.

## Three isolated variants

1. **Pristine:** all production source bytes unchanged.
2. **Observer:** a copied `voice.c` includes a host-only header. It samples
   inactive/gated slots at rendering boundaries and records the actual gate masks,
   phase/fade and NOTE suppression at `trk_note_on`'s phrase decision. It returns
   the original nonzero/zero gate predicate. Its file IO makes timing comparisons
   invalid and must never enter a target build.
3. **Counterfactual:** the same host instrumentation, with only the fresh-phrase
   predicate changed from `OR(gate)` to `OR(gate && active)`. Consequently the
   existing phase/fade reset may run. It changes no voice's gate, active, stage,
   envelope, note ownership or engine-specific state.

The third variant is deliberately **narrower than full retirement**. Clearing
voice fields or changing allocation, sustain, mono priority, engine reset or
DRUM identity checks could have additional effects. These results do not qualify
such changes or their interrupt cost.

The source transformation requires one exact phrase-loop anchor and one exact
`track_render` signature. Missing, duplicate or changed anchors fail before a
source-copy write. The emitted diff and before/after hashes expose every change;
no production file or target build flag enables this observer.

## Workloads and results

Each variant ran the existing `regress` harness against the committed
`tests/golden.txt`, with CPU_FILE explicitly `-`. All three report **98 unchanged
golden renders, zero health failures, zero voice/routing failures and zero crashes**.
CPU budgets were not checked, and no golden or budget was rewritten.

The observer recorded 11,991 note events in that complete regression invocation.
Sixty-seven encountered inactive/gated slots; twenty-five NOTE reset decisions
were suppressed exclusively by inactive gates, all on SLICE (stable engine ID
13). These counts include the harness's sound, health, voice and CPU-workload
invocations; they are not a count of audible defects or unique musical phrases.
The counterfactual still passes the existing sound goldens, so that suite alone
does not reveal the targeted PCM difference.

All eight real stress schedules were generated by the existing frozen
`stress_matrix.py` validator/header writer and replayed through the existing
`stress_render.c` at `-O2`: idle, shared-eight, voice pressure, active effects,
engine-switch tails, dense ratchets/modulation, effects throws and USB/TRS MIDI.
The existing matrix health checks pass, and observer PCM matches pristine bytes
for every schedule. There are no inactive-gate-only suppression events in these
schedules; counterfactual PCM also matches. This is scoped replay coverage, not
a run of the matrix CLI's separate `-Os`, repeat, instruction-count and negative
control workflow.

The focused harness runs 21 fresh-process cases: SAMPLE, SLICE, GRAIN, DRUM and
LOFI, each with a held first key, released first key, repeated same pitch and a
real engine-switch fade, plus a GRAIN user-zone key-gap case. It uses native MIDI
ownership and real exported sample material, requires NOTE trigger, and sets
LFO pitch depth to 48 (legal range -64..63) to expose a phase difference. Every
configured parameter is checked against its native descriptor before rendering.
SAMPLE is non-looping PIANO;
SLICE is BREAK/ONE; GRAIN uses real PIANO; LOFI is STEP LEAD. The key-gap case uses
a synthetic one-zone user key map over actual factory ADPCM, with only MIDI 64
mapped: MIDI 60 intentionally produces native unmatched-key silence. It does not
claim coverage of flash upload or user-slot scanning.

The second note occurs at frame 88,224 in the held cases (whole control blocks).
In the three differing cases, the observed second-note phase/fade remains
`2147796414 / 32767`; the counterfactual resets it to the configured
`771751936 / 0`. Every observer focused PCM file **and complete sampled
voice/ownership state** matches pristine. The counterfactual differs in three of
21 focused PCM files; all remaining focused files match. JSON retains complete
PCM hashes and first differing byte/frame rather than relying on listening.

All sampled focused inactive/gated voices have a logical MIDI owner. Releasing
the first key clears its gate even if its audio has already ended, as the current
`trk_note_off` implements. LOFI STEP's released control reaches
active/gate/stage/envelope = `0/0/0/0`. No orphan claim is inferred from the
regression's direct note calls or from unobserved UI/sequencer paths. Observer
block counters are cumulative samples at transitions/note events, not final
process-wide totals or device timing.

## Reproduce and inspect

From a trusted checkout with the normal [build prerequisites](../BUILDING.md), a
host C compiler, initialized/cached exact Engines objects and the explicit real
CC0 library (see `tools/fetch_cc0.py`), run:

```sh
uv run --locked --group build python tools/retirement_measure.py \
  --ref 1523fd0e9bb1483082ba5a71834e7255c04e7ff5 \
  --samples-dir /absolute/path/to/assets/samples-cc0 \
  --out build/issue309/reproduction-1
```

The output directory must be new. `--focused-only` is a shorter development run
and explicitly omits existing regression/stress coverage. It does not satisfy the
complete procedure above. No donor scripts are executed and no device is opened.

Author evidence is under ignored `build/issue309/full-4/summary.json` and its
sibling snapshots/logs/PCM. Earlier `focused-2` and `full-1` through `full-3` runs
used an out-of-range exploratory LFO pitch depth (110) and do not support the
final claim. They are retained to expose that correction. The final run uses
depth 48, validates every configured parameter, asserts focused-state equivalence
and invokes the existing stress health checks. An initial metadata-generation
prerequisite error is preserved in `focused-1`; it ran no audio tests. Three deliberate anchor faults
(missing phrase, duplicate phrase, changed render signature) were rejected
without writing their input copies; evidence is
`build/issue309/negative-anchor-checks.json`.

### User test instructions

1. Run the command above with your explicit CC0 path and a fresh output directory.
   Expect successful exit and `passed_observer_equivalence` in `summary.json`.
2. Check that all 29 observer PCM comparisons and all 21 focused state comparisons
   are equal. Inspect the three counterfactual differences and their held-owner
   states; released and same-pitch controls must remain equal.
3. Check all three `regress.log` summaries: 98 unchanged goldens and CPU budget
   explicitly not checked. Inspect stress health states and source/overlay hashes.
4. Inspect `host-only-voice.patch`: production instrumentation exists only in the
   ignored observer/counterfactual copies. Report source/pin, compiler, command,
   summary and failing workload if any result differs. Keep the retained directory
   for review; there is no device or stored-music cleanup.

No firmware target build, `-Os` matrix CLI, full host suite, browser emulator or
real FM-1 run was performed for this tooling package. They are not claimed as
passing. No app/RAM/POOL/RAMTEXT/NOINIT/stack delta, target deadline, host CPU gain
or physical listening result was measured. No hardware test is necessary to
accept this offline observation tool; a future firmware behavior change would
require its own target and device qualification.
